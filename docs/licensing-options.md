# Варианты лицензирования WISLA FM

Основано на публичных моделях конкурентов (август 2026) и позиционировании «продаём только модуль FM». Не прайс и не оферта. Решение по цифрам — [FM-5](../BACKLOG.md). Сводка рынка: [go-to-market.md](go-to-market.md). Текст для маркетинга и КП: [licensing-for-marketers.md](licensing-for-marketers.md).

## 2. Ограничения нашей модели

Должно быть правдой на КП:

- покупают **модуль**, не мониторинг;
- не штрафуем за несколько источников (Zabbix + Alertmanager + OSS);
- дешевле полки Monq Business (~1,2 млн ₽), иначе нет клина;
- не конкурируем с Zabbix $0;
- on-prem / закрытый контур — основной контур;
- клиенты wiSLA должны докупать дешевле, чем с нуля.

## 3. Варианты для WISLA FM

Четыре рабочих схемы. Можно сочетать форму оплаты (3) с метрикой (1 или 2).

### Вариант A — пакеты продуктов (рекомендуемый рост)

**Аналог:** пакеты хостов Proto, но единица — **продукт** в графе здоровья, не хост.

**Как устроено.** Право на экземпляр модуля + ступени: 1 / 5 / 15 / безлимит продуктов. Источники и пользователи консоли — безлимит (или высокий потолок).

| Ступень | Для кого | Роль в воронке |
|---|---|---|
| 1 продукт | Пилот, Gift Shop / один ДБО | Снять страх замены Zabbix |
| 5 | Типичный NOC нескольких услуг | Основная полка |
| 15 | Крупный ИТ / несколько площадок | Рост без смены модели |
| Безлимит | Холдинг | Потолок ниже Monq Business |

**Плюсы.** Метрика совпадает с УТП («здоровье продукта»). Закупка понимает пакеты. Расширение = докупка пакета, не новая платформа. Не бьёт сегмент «много источников».

**Минусы.** Нужно жёстко определить «продукт» (ячейка здоровья, не КЕ и не хост). Заказчик может дробить продукты, чтобы сэкономить — тогда в договоре: продукт = объект на тепловой карте, который видит смена.

**Коридор (гипотеза, не КП).** 1 продукт — вход / пилот. 5 продуктов — заметно ниже 1,2 млн ₽ (ориентир «между Monq Core и Business»). Безлимит — всё ещё ниже Business, иначе клин мёртв.

---

### Вариант B — плоский инстанс + сопровождение

**Аналог:** OpenNMS Meridian (плата за сервер, узлы безлимит) + Zabbix (софт отдельно от support).

**Как устроено.** Одна лицензия на контур (prod FM + adapter). Продукты, источники, дежурные — безлимит. Деньги: лицензия модуля + ежегодное сопровождение (SLA, обновления). Второй контур (тест/DR) — процент от боевого или бесплатно.

**Плюсы.** Проще всего для тендера и ИБ: «купили модуль». Нет споров, что считать продуктом. Хорошо для сегмента A (wiSLA) и банков с одним контуром.

**Минусы.** Слабый upsell: крупный и мелкий платят похоже. Мелкому NOC может быть дорого, холдингу — дёшево. Нужна дисциплина: не плодить «бесплатные» продукты без цены внедрения.

**Коридор (гипотеза).** Лицензия модуля в зоне Monq Core (от ~500 000 ₽), не Business. Сопровождение 18–25% в год — привычно коробке. Не ставить support-only как Zabbix: у нас нет бесплатного софта.

---

### Вариант C — две формы оплаты, одна метрика

**Аналог:** Monq (бессрочно или подписка), SimpleOne (cloud год / on-prem бессрочно).

**Как устроено.** Метрика A или B, но касса на выбор:

| Форма | Кому | Типичная конструкция |
|---|---|---|
| Подписка 12 мес | Коммерция, пилот → продление | Ниже вход, проще добавить пакет продуктов |
| Бессрочно + сопровождение | Гос, закрытый контур, capex | Выше вход, 20%± в год |

Множитель: бессрочная ≈ 2–2,5 годовых подписки (как часто делают в коробке), чтобы не каннибализировать подписку.

**Плюсы.** Закрывает оба контура закупки без второй продуктовой линейки.

**Минусы.** Два прайса надо считать аккуратно. Облако Wellink — та же подписка, не третья метрика.

---

### Вариант D — докупка к wiSLA (attach)

**Аналог:** нет прямого (у конкурентов FM спрятан в платформу). У нас это УТП.

**Как устроено.** Тот же FM, что в A/B, но SKU «FM для wiSLA»: скидка 20–35% или включённый пакет «1–5 продуктов» в договор wiSLA. Без wiSLA — полная цена A/B.

**Плюсы.** Сегмент A (первый приоритет). Не отдаём FM бесплатно «в нагрузку» ко всему wiSLA — модуль остаётся видимой строкой.

**Минусы.** Если скидка слишком глубокая, независимый Zabbix-клиент обидится. Нужна явная полка «FM standalone» vs «FM attach».

## 4. Что не предлагать

| Схема | Откуда соблазн | Почему ломает позицию |
|---|---|---|
| Хосты / NVPS / агенты | Proto, GMONIT, Пульт, Zabbix Cloud | Продаём сбор, которым не являемся |
| FM только в «Максимум / Business» | Monq, ИнфраМенеджер | Клиент должен купить платформу, чтобы получить консоль — против УТП |
| Community как основной продукт | Monq, Zabbix, OpenNMS Horizon | Смешивает с OSS-мониторингом, обесценивает модуль |
| По операторам консоли | SimpleOne | Дежурных мало; рост не про людей в UI |
| По числу источников | — | Штраф за Zabbix+AM+OSS — наш лучший кейс |
| Только внедрение, софт $0 | NOC Project, интеграторы Zabbix | Wellink — вендор модуля, не час интегратора |

Триал 60–90 дней на 1 продукт — да. Бессрочный бесплатный Community — нет.

## 5. Сборка «как продавать»

Рекомендуемая комбинация: **A + C + D**.

1. Метрика роста — **пакеты продуктов** (A).
2. Касса — **подписка или бессрочно** (C).
3. Отдельная цена **attach к wiSLA** (D).
4. Пилот = ступень «1 продукт», не отдельный урезанный продукт.
5. Источники и пользователи консоли не тарифицировать.
6. Сопровождение всегда явной строкой (урок Zabbix/Icinga), но софт не отдавать бесплатно.

Вариант B оставить запасным, если закупка отказывается считать продукты: тогда один инстанс, рост через внедрение и второй контур, не через хосты.

### Условные SKU

| Код | Состав | Форма |
|---|---|---|
| `FM-PILOT` | 1 продукт, 90 дней | NFR или зачёт в первый год |
| `FM-5` / `FM-15` / `FM-UL` | Модуль + пакет продуктов | Подписка *или* бессрочно |
| `FM-WISLA` | Тот же пакет, attach-скидка | Только при действующем wiSLA |
| `FM-SUP` | Сопровождение, SLA | Ежегодно, обязательно на бессрочной |

Цифры ступеней в ₽ — отдельное решение коммерции; ориентир только один: **рабочий пакет должен быть дешевле Monq Business (~1,2 млн ₽)**.
